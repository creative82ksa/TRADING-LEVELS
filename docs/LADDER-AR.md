# كيف نبني سلّم السيولة (Liquidity Ladder)

الشاشة في الصورة المرجعية ليست مؤشراً ولا نموذج ذكاء اصطناعي — هي **عرض
مباشر لسلسلة العقود (option chain)** مرتّبة عمودياً حسب الاسترايك. كل ما فيها
مشتق من أربعة أرقام لكل استرايك: سعر الكول، سعر البوت، العقود المفتوحة،
والفوليوم. الباقي تنسيق.

## 1. البنية

```
مصدر البيانات  →  طبقة التطبيع  →  لقطة (snapshot)  →  العرض
  FlashAlpha        build_snapshot.py    data/*.json      render.py
```

الفصل بين الطبقات مقصود: طبقة العرض لا تعرف شيئاً عن المزوّد، فلو بدّلنا
FlashAlpha بـ IBKR أو ببثّ websocket، يتغيّر السكربت الأول فقط.

## 2. مصدر البيانات

نستخدم ثلاث نقاط من FlashAlpha:

| النقطة | ما تعطيه | دورها في الشاشة |
|---|---|---|
| `/v1/option/quote?symbol=&expiry=` | كل عقود التاريخ: bid/ask/mid، IV، الجريكس، `open_interest`، `volume` | أعمدة الأسعار + طول الأشرطة |
| `/v1/exposure/sheet?symbol=` | `call_oi` و `put_oi` لكل استرايك عبر كل التواريخ | احتياطي للـ OI قبل الافتتاح |
| `/v1/flow/levels?symbol=&expiry=` | `live_call_wall`، `live_put_wall`، `live_max_pain` | الصفوف المتقطّعة (المستويات المفتاحية) |

نداء واحد لـ `option/quote` بدون تحديد استرايك يرجّع السلسلة كاملة — هذا هو
النداء الرئيسي، والاثنان الآخران إثراء.

## 3. التطبيع — `ladder/build_snapshot.py`

المزوّد يرجّع قائمة مسطّحة: صف لكل عقد (كول وبوت منفصلين). السلّم يحتاج صفاً
واحداً لكل استرايك، فنطوي القائمة:

```json
{ "strike": 7700, "call_price": 3.50, "put_price": 44.45,
  "call_oi": 8600, "put_oi": 3999, "liquidity": 12599 }
```

ثلاث قرارات مهمة هنا:

- **النافذة**: نعرض ±15 استرايك حول السعر الحالي فقط. السلسلة الكاملة 509
  استرايك، ولا معنى لعرض 3200 و10000 في شاشة تداول لحظي.
- **مقياس الشريط**: الفوليوم أثناء الجلسة (يعكس نشاط اليوم)، والعقود المفتوحة
  خارجها (الفوليوم يصير صفراً). هذا هو خيار `--metric`.
- **أقوى العقود**: نرتّب جهة OTM فقط. استرايك داخل السعر (ITM) يحمل أحجاماً
  ضخمة لأسباب لا علاقة لها بمضاربة اليوم، فإدخاله يفسد الترتيب.

## 4. العرض — `ladder/render.py`

كل صف شبكة من أربعة أعمدة: الاسترايك، مسار الشريط، سعر الكول، سعر البوت.
عرض الشريط = `liquidity / أعلى سيولة في النافذة × 100%`، أي نسبي للشاشة لا
مطلق — وهذا ما يجعل جدار العقود يبرز بصرياً.

اللون يتبع موقع الاسترايك من السعر: أخضر فوقه (منطقة الكول)، أحمر تحته
(منطقة البوت). صف السعر الحالي يُحقن بين الاسترايكين المحيطين به، والمستويات
المفتاحية تُرسم كخط متقطّع داخل الصف.

## 5. التحديث اللحظي

النسخة الحالية تولّد صفحة ثابتة. للتحديث المستمر أمامك ثلاثة مستويات:

1. **الأبسط**: `<meta http-equiv="refresh" content="5">` مع إعادة توليد
   الـ snapshot كل خمس ثوانٍ عبر cron. يكفي للمتابعة على الجوال.
2. **الأنسب**: تحويل `render.py` إلى قالب يقرأ `snapshot.json` عبر `fetch()`
   كل ثانيتين ويحدّث الـ DOM. الصفحة تُحمّل مرة واحدة.
3. **الأدق**: بثّ websocket من المزوّد مباشرة إلى المتصفح، مع الاحتفاظ
   بـ `build_snapshot.py` كمنطق تطبيع مشترك.

## 6. ما ينقص مقارنة بالصورة المرجعية

- **العدّاد الزمني** (`15:17:55`): وقت متبقٍّ حتى الإغلاق — حساب محلي بسيط.
- **الأسهم العلوية**: مؤشرات تدفّق (اتجاه الأوامر)، تحتاج `/v1/flow/live`.
- **تتبّع تغيّر OI لحظياً**: `/v1/oi/diff` يعطي الفرق اليومي، لكن الفرق
  اللحظي يحتاج تخزين لقطات متتابعة والمقارنة بينها.

## 7. التشغيل

```bash
# 1. احفظ ردود الـ API الثلاثة في ملفات JSON
# 2. ابنِ اللقطة
python3 ladder/build_snapshot.py \
  --quotes raw/quotes.json --exposure raw/exposure.json --levels raw/levels.json \
  --symbol SPX --width 15 --metric open_interest \
  --out data/SPX-2026-09-21.json

# 3. ولّد الصفحة
python3 ladder/render.py data/SPX-2026-09-21.json --out ladder.html
```

## ملاحظة على البيانات

اللقطة المحفوظة في `data/` أُخذت خارج ساعات التداول، لذلك `volume` صفر في كل
العقود والأشرطة مبنية على العقود المفتوحة. أثناء الجلسة شغّل الأمر بـ
`--metric volume` للحصول على الصورة التي تطابق المرجع.
